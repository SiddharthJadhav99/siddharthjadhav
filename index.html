Selected work

Systems I designed or built, with the numbers they moved. Open any card for the full story.

  • The problem

    Complex decisions and business processes depended on people moving information between systems and making the same judgment calls by hand.

    What I’m building

    Agentic workflows built with Microsoft Agent Framework and LangGraph. Agents plan the steps, call tools and internal systems, and hand off to each other, with machine learning models integrated where predictions drive the decision.

    How I keep it production grade

    Agents are treated like any other service: observable, testable, and owned. I work across teams so the workflows stay fast, reliable and maintainable rather than fragile prototypes.

    Details are kept general because this work is confidential.

  • The problem

    Messages arrived in very different sizes: roughly 5% large, 20% medium and 75% small. Processing them together meant large payloads slowed everything behind them.

    What I built

    A partition grouping approach in Java and JavaScript that routes messages by size class, so heavy messages stop blocking the light ones that make up most of the traffic.

    The result

    Message processing latency dropped 33% and throughput rose from 18K to 24K events an hour.

  • The problem

    Pharmaceutical companies must report transactions to regulators in each country, on time and without errors, at very high volume.

    What I built

    RESTful Java APIs for several country compliance apps, plus parts of the system design for event-driven features connected through GraphQL APIs and Kafka. Message handling is idempotent, so retries never create duplicate filings.

    The result

    More than 800,000 transaction reports a week flow securely to regulatory reporting systems.

  • The problem

    Each migration to BigQuery meant writing new pipeline code per source database and per table.

    What I built

    A reusable ingestion framework in Java on Apache Beam, running on Google Cloud Dataflow, that handles Oracle, Snowflake and MSSQL sources.

    The result

    Over 2TB of data across 50+ tables ingested into BigQuery. I later trained 80+ colleagues on Beam and Dataflow, which earned Trainer of the Quarter.

  • The problem

    Creating data workflows in Ascend.io was manual and repetitive, taking two to three days each.

    What I built

    A plugin in Python that drives Ascend.io through its REST APIs and generates workflows automatically.

    The result

    Workflow creation dropped to under 30 minutes, cutting manual effort by 95%.

  • The problem

    Supply chain audits needed professional transaction documents, and clients had no way to produce them at scale.

    What I built

    A bulk T2 export feature using Handlebars templates, Node.js and GraphQL, rendered to PDF with OpenHTMLToPDF.

    The result

    Clients generate more than 12,000 compliance PDFs a week for audit reporting.

  • The problem

    Transactions failed when they referenced product codes (NDCs) or partners the system didn’t recognise.

    What I built

    Automated Master Data NDC Update and Partner Master Lookup services in Java Spring that fill in validated data automatically.

    The result

    Unknown-NDC transaction errors fell by about 20%. Separately, I fixed data-loss bugs affecting 1.5M+ monthly transactions and added 15+ Grafana metrics to catch issues early.
