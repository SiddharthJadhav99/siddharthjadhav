Context

Pharmaceutical companies must report transactions to regulators in each country, on time, exactly once, and at high volume. The systems I worked on take those transactions in, enrich and validate them, and submit reports to regulatory and order management systems downstream.

Faster processing with partition grouping

Messages varied widely in size: about 75% small, 20% medium and 5% large. Processed together, large messages held up the small ones behind them.

I introduced partition grouping in Java and JavaScript, so messages of similar size are processed together and large ones no longer block the rest. Processing latency fell by 33% and throughput rose from 18,000 to 24,000 events an hour on the same infrastructure.

Compliance reporting APIs

I designed and built RESTful Java APIs for several country compliance apps. Together they submit more than 800,000 pharmaceutical transaction reports a week.

I also contributed to the design of event-driven features connected through GraphQL APIs and Kafka, with idempotent message handling so retries never create duplicate filings.

Data quality

Transactions failed when they referenced product codes or trading partners the system didn’t recognise. I built automated master data and partner lookup services in Spring that fill in validated data first. Unknown-product errors fell by about 20%.

I also delivered void transaction handling in Scala and JavaScript, processing more than 10,000 voids a month under US supply chain rules (DSCSA).

Reliability and audit

I fixed critical data-loss bugs affecting more than 1.5 million transactions a month, then added over 15 custom metrics with Grafana dashboards so similar problems show up before customers notice.

For audits, I built a bulk export with Node.js, GraphQL and Handlebars templates rendered to PDF. Customers now generate more than 12,000 compliance PDFs a week.
